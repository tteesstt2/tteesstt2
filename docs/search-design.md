# 검색 처리 설계

관련 문서: [데이터 항목](./data-model-research.md), [검색·화면 데이터](./search-and-screens.md)

## 1. 전체 흐름

```
[색인 시점]  장면 저장/검증 변경
   → 검색 문서 생성(평탄화) → 텍스트 색인 + 임베딩 생성

[검색 시점]  사용자 검색어
   ① 정규화 → ② 검색어 해석 → ③ 3가지 검색 병렬 실행
   → ④ 결과 합치기(RRF) → ⑤ 순위 보정 → ⑥ 묶기/중복 제거 → 결과
```

## 2. 기술 선택

| 단계 | 추천 | 이유 |
|---|---|---|
| 시작 (PoC~초기) | **PostgreSQL + PGroonga + pgvector** | DB 하나로 해결. PGroonga는 일본어·한국어 전문 검색 지원 (기본 PostgreSQL 전문 검색은 한·일 단어 분리를 못함) |
| 규모 확대 시 | OpenSearch (kuromoji·nori 형태소 분석 + 벡터 검색) | 대용량, 세밀한 랭킹 튜닝 |

검색 로직은 별도 모듈(`SearchService`)로 감싸 엔진을 바꿔도 화면·API는 그대로 두게 한다.
> 확인 필요: 사용할 DB 호스팅이 PGroonga를 지원하는지 (예: Supabase 지원, AWS RDS 미지원).

## 3. 색인 시점 처리

| 작업 | 내용 |
|---|---|
| 검색 문서 생성 | 장면 1개 = 문서 1개. 장소명(다국어·별칭·**상위 장소명 포함**), 지역, 역, 화면 글자, 음성, 요약(ko/ja/en), 태그, 영상 제목, 채널 |
| 임베딩 생성 | `요약 + 태그 + 장소명`을 합친 텍스트를 다국어 임베딩 모델(Gemini 임베딩)로 벡터화 |
| 별칭 생성 | 장소 검증 시 Gemini로 한국어·영어 표기, 가나 읽기 후보 생성 → 관리자 확인 후 PlaceName에 저장 |
| 재색인 조건 | 장면 수정, 장소 검증·수정·병합, 별칭 추가 시 관련 문서만 갱신 |

## 4. 검색 시점 처리

### ① 정규화
- 유니코드 NFKC (전각→반각), 영문 소문자화, 공백 정리
- 가타카나 ↔ 히라가나 통일 (アサクサ = あさくさ)

### ② 검색어 해석 (사전 기반, 빠름)

검색어를 단어로 나눠 사전과 맞춘다.

| 사전 | 출처 | 예 |
|---|---|---|
| 장소 사전 | PlaceName 전체 | 센소지 → 浅草寺, 이치란 → 一蘭 |
| 지역·역 사전 | Place의 지역·역 값 + 별칭 | 시부야 → 渋谷区 / 渋谷駅 |
| 태그 동의어 사전 | 직접 관리 (ko/ja/en) | 야경·밤 → night, 비 → rain, 먹방 → eating, 라멘·ラーメン → ramen |

해석 결과는 **강제 필터가 아니라 가산점**으로 쓴다 (사용자 의도가 다를 수 있으므로). 화면에서 직접 고른 필터만 강제 필터.

사전으로 해석이 안 되는 긴 문장은 Gemini로 해석하는 옵션을 두되, 비용·속도 때문에 결과를 캐시하고 기본값은 끈다.

### ③ 3가지 검색을 동시에 실행

| 검색 | 대상 | 잡아내는 것 | 후보 수 |
|---|---|---|---|
| 키워드 | 전 필드, 가중치 적용 (장소명 > 지역·역 > 화면 글자·음성 > 요약 > 태그 > 제목) | 정확한 이름 | 상위 100 |
| 오타 허용 | 장소명·지역명 n-gram 유사도 | "아사쿠시", "sibuya" | 상위 50 |
| 의미(벡터) | 검색어 임베딩 ↔ 장면 임베딩 | "비 오는 밤 골목" | 상위 100 |

### ④ 결과 합치기: RRF (Reciprocal Rank Fusion)

각 검색의 **순위**만 사용해 합산한다. 점수 단위가 달라도 되고 튜닝이 거의 필요 없다.

```
score(장면) = Σ 1 / (60 + 각 검색에서의 순위)
```

### ⑤ 순위 보정

| 요소 | 방향 |
|---|---|
| ②에서 해석된 장소·지역·태그와 일치 | 크게 + |
| 장소 검증됨 (`verified`) | + |
| 근거가 `observed` / 높은 `confidence` | + |
| 최신 영상 | 약간 + |
| 장소 미특정 장면 | 약간 − (의미 검색 결과로는 유지) |

### ⑥ 묶기·중복 제거
- 한 영상에서 최대 2~3개 장면만 노출 (같은 영상 도배 방지)
- 연속된 같은 장소 장면은 하나로 합침
- 검색어가 특정 장소로 해석되면 목록 위에 **장소 카드** (지도·주소·장면 수) 표시 — 구글 지식 패널처럼

## 5. 부가 기능

| 기능 | 처리 |
|---|---|
| 자동완성 | PlaceName·지역명 앞부분 일치 + 인기 검색어 |
| 혹시 이것? | 결과 0건 또는 적을 때 오타 허용 검색으로 가장 가까운 장소명 제안 |
| 조건 완화 | 결과 0건이면 필터·지역 가산점을 풀고 의미 검색 결과만 보여줌 |
| 하이라이트 | 어떤 필드가 매칭됐는지 표시 (예: "간판 글자 '雷門' 일치") |

## 6. 처리 예시: `시부야 비오는 밤 라멘`

1. 정규화 → `시부야 비오는 밤 라멘`
2. 해석 → 지역 `渋谷`, 태그 `rain`, `night`, 품목 `ramen`
3. 키워드: 渋谷·ラーメン·라멘 포함 장면 / 오타: 해당 없음 / 의미: "비 오는 밤에 라멘" 비슷한 장면
4. RRF로 합침
5. 渋谷 지역 + rain + night + ramen이 모두 맞는 장면을 크게 올림
6. 영상당 2~3개로 제한 → 결과

## 7. 품질 관리

- **테스트 검색어 세트**: 50~100개 검색어 + 기대 결과를 만들어 변경 시마다 정확도 측정
- **로그**: 결과 0건 검색어, 클릭 안 된 검색어 수집 → 동의어·별칭 사전 보강
- 순위 가중치는 설정값으로 빼서 코드 수정 없이 조정
